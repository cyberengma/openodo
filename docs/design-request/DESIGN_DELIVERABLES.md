# Design Deliverables

The design agent must return a package containing the following.

## Required files

- `README.md` — package map and design decisions.
- `product-overview.md` — product goals, users, constraints, and scope.
- `navigation.md` — destinations, entry points, back behavior, and state flow.
- `screen-vehicle.md`
- `screen-dashboard.md`
- `screen-fuel.md`
- `screen-fuel-history.md`
- `screen-record-entry.md`
- `screen-records.md`
- `screen-reminders.md`
- `screen-reminder-edit.md`
- `screen-statistics.md`
- `screen-settings.md`
- `screen-portability.md`
- `components.md` — component inventory and variants.
- `states.md` — loading, empty, warning, error, and validation matrix.
- `accessibility.md` — accessibility and responsive decisions.
- `decisions.md` — resolved choices and remaining questions.
- `traceability.md` — domain capability to screen/component mapping.

## Every screen file must contain

- Purpose.
- User goal.
- Entry points.
- Layout hierarchy.
- Content and fields.
- Primary action.
- Secondary actions.
- Navigation outcomes.
- Loading state.
- Empty state.
- Warning state.
- Error state.
- Validation rules.
- Destructive actions.
- Accessibility semantics.
- Phone and large-screen behavior.
- Light/dark behavior.
- Open decisions or explicit “none.”

## Required diagrams or equivalent

- Application navigation map.
- First-launch flow.
- Add-fuel flow for liquid and electric entries.
- Add-expense and reminder-reset flow.
- Reminder lifecycle flow.
- Import/backup flow.

Text diagrams are acceptable when they are unambiguous and versionable.
